# On-Device 画像自動入力機能 仕様書 (On-Device Image Input Spec)

## 1. 概要
本機能は、ユーザーが各証券会社アプリ等の「日次実現損益画面」や「約定履歴」のスクリーンショットを選択・撮影した際に、端末内（オンデバイス）の文字認識（OCR）およびローカル抽出パーサーを用いて、**「利益額」** と **「損失額」** を自動的に検出し、金額入力画面（`AmountInputScreen`）へ反映する機能である。

一切の外部通信（サーバーへの画像・テキスト送信）を行わず、完全なオフライン環境と最高水準のプライバシー保護を実現する。

---

## 2. システムアーキテクチャ

```mermaid
graph TD
    A[ユーザー] -->|写真選択 / 撮影| B[ImagePicker]
    B -->|画像バイト列 / ファイル| C[On-Device OCR Engine]
    C -->|認識テキストブロック群| D[TradeTextExtractor]
    D -->|抽出結果 (profit, loss, summary)| E[AmountInputScreen UI]
    E -->|自動入力反映| F[ユーザー確認・保存]
```

### 2.1 レイヤー構成
1. **Presentation層**:
   - `AmountInputScreen`: 「画像から自動入力」トリガーボタンの配置、処理中のローディング表示、抽出結果の反映とユーザー通知。
2. **Domain層**:
   - `AiExtractorPort`: 画像または認識テキストからトレード数値を抽出する抽象インターフェース。
   - `ExtractedTradeData`: 抽出された利益額・損失額・検出メタデータを保持するエンティティ。
3. **Infrastructure層**:
   - `OcrService`: プラットフォーム/オンデバイスOCRを実行し、テキストとブロック情報を取得。
   - `TradeTextExtractor`: 証券会社特有のテキスト配置（「利益」「損失」「計」「▲」「¥」等）から、確度の高い数値をパースするルールベース抽出エンジン。

## 3. UI / UX 仕様 (Design System 準拠)

### 3.1 金額入力画面 (`AmountInputScreen`) の配置
* **トリガーボタン**:
  * 日付選択欄と「利益額・損失額」入力欄の間に、自然にアクセスできるボタンを配置。
  * スタイル: `AppColors.card` 背景に細いボーダー、またはテーマカラーをアクセントとしたCupertinoスタイルの角丸ボタン。
  * 表示テキスト: `📷 スクショから自動入力`
* **アクションシート（選択ダイアログ）**:
  * タップ時に `CupertinoActionSheet` を表示：
    * `写真ライブラリから選択` (ImageSource.gallery)
    * `カメラで撮影` (ImageSource.camera)
    * `キャンセル`
* **処理中フィードバック**:
  * OCR・抽出処理中はインジケーター（`CupertinoActivityIndicator`）と「画像を解析中...」を表示し、重複タップを防止。
* **抽出完了時の挙動**:
  * 検出された「利益額」「損失額」をそれぞれの `TextEditingController` に代入。
  * 損益額（自動計算）が即時更新される。
  * 成功ダイアログまたはトースト通知を表示：
    * 例: `「利益: ¥12,500」「損失: ¥3,000」を読み取りました。内容を確認して保存してください。`
  * 抽出できなかった場合：
    * 例: `画像から利益・損失の数値を特定できませんでした。手動で入力してください。`

## 4. 抽出エンジン（TradeTextExtractor）パース仕様

日本の主要証券会社（SBI証券、楽天証券、松井証券、マネックス証券、auカブコム証券、GMOクリック証券、moomoo証券等）の日次損益画面に対応するため、以下の正規化とキーワード近傍探索を行う。

### 4.1 テキストの正規化
1. 全角英数字・記号を半角に変換（`０-９` → `0-9`、`，` → `,`、`￥` → `¥`）。
2. 空白・改行の正規化。
3. 金額表記（カンマ区切り、`¥` 記号、`円` 単位）のパース。
4. 負数記号の標準化（`-`、`▲`、`△`、`▼`、`赤字` → マイナス数値）。

### 4.2 キーワードマッチングルール
* **利益キーワード**:
  * `利益`、`実現利益`、`売買益`、`決済益`、`益`、`Profit`、`受取`
* **損失キーワード**:
  * `損失`、`実現損失`、`売買損`、`決済損`、`損`、`Loss`、`支払`
* **近傍探索ロジック**:
  1. キーワードと同一行にある金額数値を優先検出。
  2. 同一行にない場合、キーワードの直下（次の行）にある金額数値を探索。
  3. 「利益合計」「損失合計」等の合計表記を最優先。
  4. 「実現損益」や「差引損益」のみで内訳（利益・損失）が分かれていない場合は、プラスなら利益額、マイナスなら損失額として割り当て。

## 5. プライバシー & セキュリティ

* **完全端末内処理**:
  * 画像ファイルおよび認識テキストは端末内部のメモリ上でのみ処理され、いかなる外部サーバーにも送信されない。
* **利用規約・プライバシーポリシー**:
  * 外部への個人情報・取引情報の送信が発生しないため、利用規約およびプライバシーポリシーの改訂は**原則不要**。
  * ユーザーの安心感のため、画面上に「※画像は端末内でのみ安全に解析され、外部には送信されません」との注記を添える。
